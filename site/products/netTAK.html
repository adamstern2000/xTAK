The operating layer
for every mobile
xTAK device.

netTAK is the base platform that runs on every Pi-class mobile xTAK device — sdrTAK, chatTAK, loraTAK, digiTAK, baseTAK Lite. It manages each device's services and exposes a unified admin surface. Use a netTAK standalone for a remote single-site role, or mesh multiple together over Wi-Fi, Ethernet, and (optionally) Wi-Fi HaLow for ridge-to-ridge ranges.

SCENARIO

Five Pis.
One self-healing mesh.
A real LAN across miles.

A wildland fire crew is operating in mountainous terrain over a five-day deployment. The Incident Command Post is at the trailhead, three squad bases are spread across the operations area, and a logistics camp is set up at the watering point two miles downhill. Cellular is dead. The radios work for voice but can't carry the IC's map. Starlink is unreliable under the canopy.

The crew deploys a netTAK at every site — five nodes in total, each in a Pelican case, each running on a 12V battery. The nodes auto-form a self-healing 802.11s + BATMAN mesh. Some hops are short-haul 2.4 / 5 GHz Wi-Fi between adjacent sites; others are 802.11ah HaLow with a small Yagi pointed up a ridge for the long-haul links.

Every netTAK runs the xTAK services the crew needs in the field: a baseTAK Lite serving a tactical map browser to anyone on the mesh, a digiTAK feeding the regional ham network into the mesh-wide TAK picture, a chatTAK letting volunteers join via their phones at any site, and an sdrTAK at the IC's node watching for inbound mutual-aid helicopters.

When one of the squad sites' uplink fails — antenna knocked over by a branch, battery low — the mesh re-routes around it within seconds. The squad's view of the TAK picture stays current. Their chat lands at the IC's tent without anyone touching a config.

Five Pis. One self-healing mesh. A real LAN across miles of fire ground.

WHAT YOU CAN DO

Four things
netTAK will do.

OUTCOME 01

Run xTAK on every field device

netTAK is the base operating layer for every mobile xTAK device. Pick the service that fits the role — sdrTAK on the device with line-of-sight to the sky, loraTAK on the device with the Meshtastic radio, chatTAK at a volunteer post, digiTAK at the radio shack, baseTAK Lite at the IC's site — and netTAK runs it as a managed service.

  • One install workflow for the whole suite — each xTAK service runs as a managed unit on netTAK with lifecycle, config, logging, and admin handled by the platform.
  • Unified admin surface — one web UI per device shows the running services, their status, and the device's role.
  • Fleet management — when netTAKs see each other, every netTAK can see the status of every other netTAK on the mesh. Restart services, push config, check status across the entire field deployment from one node.
  • Same services that ship standalone — sdrTAK, loraTAK, digiTAK, chatTAK, and baseTAK Lite all run on netTAK as the same products you'd install on a bare Pi today.
OUTCOME 02

Mesh them together — or run a single node standalone

netTAK supports three deployment patterns. Pick the one your operation needs; mix and match across sites.

  • Standalone — a single netTAK running its xTAK services, no mesh required. For remote outposts, single-site deployments, or any role that doesn't need peer-to-peer routing. Joins the local TAK LAN like a fixed install.
  • Local mesh (Wi-Fi + Ethernet) — multiple netTAKs auto-mesh over the Pi's built-in Wi-Fi and/or wired Ethernet. No specialty radios, no licensed spectrum, no cost beyond the Pis.
  • Long-range mesh (with Wi-Fi HaLow) — add 802.11ah HaLow radios to span miles between sites. Pair with directional antennas for ridge-to-ridge and watershed-to-watershed bridges.
  • Self-healing, self-organizing, layer-2 transparent — when a node drops, traffic re-routes within seconds. Standard TAK traffic crosses without translation.
OUTCOME 03

Distribute maps in the field, no Operations Center required

Every netTAK node running baseTAK Lite includes the same tileserver baseTAK runs at the EOC — so a forward site can distribute maps locally, without backhauling to headquarters and without an internet uplink in the field.

  • Pre-load the netTAK node with regional terrain (MBTiles, XYZ tile sets).
  • Live distribution to EUDs — every ATAK and WinTAK tablet that joins the local mesh pulls tiles directly from the netTAK node it can reach.
  • Sync from any forward site — operators arriving at a remote staging area can download local map sets from the netTAK there, without ever connecting to the operations center.
  • Resilient to long deployments — if the mesh hop back to the EOC fails, the local node keeps serving maps; field teams stay current.
  • Same tile format everywhere — what baseTAK serves at the EOC, baseTAK Lite serves at every forward site. One pre-load workflow.
OUTCOME 04

Add surveillance and ISR feeds

netTAK's higher bandwidth (compared to LoRa or APRS) makes it practical to carry video and other rich feeds across a deployment.

  • IP cameras at sentry points, gate checks, parking lots — visible to every TAK client on the mesh.
  • Drone telemetry and video feeds routed through the mesh to the IC's screen.
  • Sensor packages — weather stations, perimeter sensors, anything IP-based.
EVERY FEATURE

What's in the box. ★ Design phase — first ship 2026Q3 estimated

netTAK is mesh-networking infrastructure for field deployment. Drop Pi-sized boxes around an operations area and they self-organize into a wireless mesh that carries TAK traffic when there's no LTE, no satellite, and no fixed AP. The capability list below is the design target, not a shipped product.

  • 802.11s mesh + B.A.T.M.A.N. routing on stock Linux Wi-Fi — no custom radio drivers.
  • Wi-Fi HaLow (802.11ah) for long-range, low-bandwidth backhaul between sites.
  • Local DHCP / DNS / HTTPS termination so TAK clients on the mesh don't need to know anything about it.
  • Self-configuring backbone — drop a node, it joins. No keys, no console, no provisioning.
  • Gateway role — one node can bridge the mesh to an upstream LTE, satellite, or internet pipe.
★ Choose netTAK when

You're running an exercise, SAR operation, festival, or remote camp where there's no infrastructure and you want the TAK picture to work across kilometers of self-mesh radio. Currently design phase — first ship 2026Q3 estimated.

FAQ

Questions
operators ask.

When will netTAK ship?

First public release is expected later this year. Hardware platform is validated and the xTAK service stack is in lab testing. Early Adopters get the Beta build the moment it's cut.

Do I have to use Wi-Fi HaLow?

No. HaLow is optional. Standalone deployments use the Pi's built-in Wi-Fi. Local mesh works over standard Wi-Fi or wired Ethernet. HaLow is only needed when you want to bridge miles between sites with directional antennas.

Can a single netTAK run multiple xTAK services?

Yes — node configuration selects which xTAK services run; nothing required, everything optional. A typical deployment has one service per node (sdrTAK at the airport, chatTAK at a parking lot, etc.), but a single node can host multiple.

What's the difference between baseTAK and baseTAK Lite?

baseTAK Lite is the variant of baseTAK that runs on a netTAK field node — same tileserver capability, multi-user web UI, but stripped down for the field-deployable form factor. The full baseTAK is the fixed-install EOC version.

How is the mesh routed?

802.11s + BATMAN — the IEEE wireless mesh standard plus the BATMAN routing protocol, both open source and production-deployed. Self-healing on node failure, self-organizing on node join. Layer-2 transparent — standard TAK traffic crosses without translation.

Do I need a commercial mesh-router vendor?

No. Standards-based 802.11s and BATMAN, your hardware, your Linux, your Pis.
